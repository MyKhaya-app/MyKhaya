# Security Policy

Do not report suspected vulnerabilities through public GitHub issues.

Before public release, configure a private security-reporting email address and publish supported-version and response expectations here.

Researchers must not access, alter or publish real user data, degrade the service or conduct destructive testing without explicit permission.

Stable production releases are promoted through `main` and stable version tags (`vMAJOR.MINOR.PATCH`).

Do not include sensitive exploit detail in public release notes before users can update safely.
